# 编辑内核与接口

编辑内核通过不可变状态和原子事务表达编辑操作，C++ 分析与缩进服务只提供查询结果或事务。前端和输入设备通过这些接口接入编辑器。

## 状态与事务

`EditorState` 持有 `Snapshot` 和一个带方向的 `Selection`。位置使用 UTF-8 字节偏移，编辑范围与选区必须落在字符边界。`Snapshot` 保留 LF/CRLF 和原有 tab/space 字节，并提供逻辑行索引。

`Transaction` 的所有修改范围指向同一基准版本。提交前统一校验版本、范围、重叠和结果选区，校验失败保留原状态。相邻修改可以组合，同一位置的多次插入需要由发起者先合并。显式结果选区使用修改后坐标，未提供时由 `ChangeMap` 映射原选区。

`ChangeMap` 的 Before/After 关联规则决定插入点和被替换范围内部的位置落到哪一侧。它可以用于更新调用者持有的位置，不能用来证明后台语义结果仍有效。

`Editor` 管理历史。一个事务是一个撤销单位，连续事务可通过显式 `history_group` 合并。撤销与重做恢复文本和选区，同时递增状态版本；过期事务不能因为恢复了旧文本而重新变为有效。选区变化通过事务提交，但单独的选区变化不生成文本撤销记录。

## C++ 分析与输入操作

本节描述当前实现。目标查询与输入协调边界见[交互缩进设计与契约](indentation.md)；现有返回字段尚不是稳定扩展协议，求解规则限定为语言内部实现。

`parse_snapshot_with_options` 共享快照文本，并使用 `CppRules.parser_options()` 建立完整词法与结构分析。`parse_snapshot` 是默认 parser 配置的便捷入口。结构节点只通过只读接口访问，记录父子关系、token 范围、缺失 token 与不完整状态。分析同时保存使用的 parser 配置；调整缩进宽度可以继续查询同一结构树，调整宏分类必须重建分析。递归深度有上限，过深或受损输入进入消耗 token 的恢复路径。

格式分析保留完整 token 流和 `Vec` 中的轻量结构记录。`parser.rs` 管理扫描与容错状态，`syntax.rs` 提供只读结果和共享的格式事实查询。分析完成后建立 token 所属结构索引；括号组、宏控制头、直接逗号和构造函数冒号的判断由分析结果统一提供，缩进与表达式重放共用。

token 所属结构按半开的 token 范围确定，零宽缺失节点不拥有 token；插入位置查询可以落在结构边界或空白处，具有独立含义。节点和 token 下标仅对所属分析结果有效。预处理分类限制在指令的逻辑行内，分支消费、退出作用域和 extern 声明头使用明确状态。

`compute_indent` 接收已编译的 `CppRules`，校验分析与快照文本、parser 配置一致，再返回结构列、固定续行列、目标列、实际空白字节、结构角色和锚点。raw string、跨行注释及配置为 whitespace-sensitive 的宏内容受到保护。预处理的 AfterHash 策略可以返回额外的局部间距修改。

`enter` 先对选区替换后的文本做词法检查，普通换行仅在换行后的临时状态上做完整结构分析并查询缩进，生成指向原状态的事务。空括号展开候选额外校验换行前的结构关系。括号之间展开、行首空白和光标位置属于同一次操作。`type_char` 处理已提交字符，访问标签、case 标签和闭合 token 的缩进变化与该字符一起撤销；粘贴应直接构造文本事务。

`reindent` 修改指定行的前导空白及必要的预处理关键字间距。结构、固定续行与对齐列分别交给空白生成器，`IndentWidth` 与非零 `TabWidth` 独立配置。

## 存储与性能边界

当前文本存储采用共享的 `Arc<str>` 和行索引。快照与历史共享已有文本；提交文本修改时构造新的完整文本和索引。这是可验证的完整存储基线，编辑成本与文档大小相关。文本容器替换时应保持事务和坐标契约。

当前分析采用完整词法和结构分析，表达式续行重放限制在 4096 个 token 的区域内。局部重分析、检查点和分析缓存需要与完整结果进行差分验证。多选区、多文档会话、字符簇导航和文件保存服务在这些接口上继续扩展。

## 验证方式

核心测试检查原子失败、UTF-8 范围、映射边界、历史分组和状态版本。语言测试检查 Enter 与输入轨迹、条件编译分支恢复、实际布局续行、空白字节、选区和撤销。

词法流应连续覆盖输入，根节点覆盖完整 token 流，子节点范围有序且属于父节点。结构语料的全部字符前缀、随机 UTF-8 输入和深度嵌套用来检验容错与终止。
