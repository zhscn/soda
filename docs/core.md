# 编辑内核与接口

编辑内核通过不可变状态和原子事务表达编辑操作，语言服务提供只读建议，editor 层将输入和建议组成事务。前端和输入设备通过这些接口接入编辑器。

## 状态与事务

`EditorState` 持有 `Snapshot` 和一个带方向的 `Selection`。位置使用 UTF-8 字节偏移，编辑范围与选区必须落在字符边界。ByteOffset、TextPoint 和 LogicalColumn 分别表达文档字节、行内字节与逻辑列，长期保留位置使用 DocumentPosition，见[坐标契约](coordinates.md)。`Snapshot` 保留 LF/CRLF 和原有 tab/space 字节，并提供逻辑行索引。

`Transaction` 的所有修改范围指向同一基准版本。提交前统一校验版本、范围、重叠和结果选区，校验失败保留原状态。相邻修改可以组合，同一位置的多次插入需要由发起者先合并。显式结果选区使用修改后坐标，未提供时由 `ChangeMap` 映射原选区。

`ChangeMap` 的 Before/After 关联规则决定插入点和被替换范围内部的位置落到哪一侧。它可以用于更新调用者持有的位置，不能用来证明后台语义结果仍有效。

`core::Editor` 是单会话适配入口，与 `editor::Document` 共用内部 `History<Owner>`。历史统一负责事务分组、逆向修改、undo/redo 分支和操作前后选区；调用方负责文本提交及会话投影。一个事务是一个撤销单位，连续事务可通过显式 `history_group` 合并。文本编辑及历史恢复递增文本修订；选区事务不推进文本修订，也不生成文本历史。净效果为空的历史分组恢复时仍推进修订，过期事务不会因恢复旧文本而重新有效。

## 文档、会话与命令循环

`editor::Document` 拥有共享文本、文本修订、撤销历史、有效语言配置和分析缓存。`EditorSession` 拥有独立选区，通过只读 `EditorState` 投影读取文档快照；投影共享 rope 和文本缓存，不单独修改文本。`EditorModel` 管理一个文档及其会话集合，`editor::Editor` 负责命令协调与提交。工作区持有这些控制器并通过 `Editing` 提供受限编辑能力，文档身份与文件绑定由工作区维护。

`DocumentId` 与 `SessionId` 是进程内不复用的标识。默认会话随模型存在，`add_session` 创建额外会话，`close_session` 关闭额外会话。关闭后，原会话标识不能继续执行命令，历史不因会话关闭而消失。

`execute` 面向默认会话，`execute_for` 显式指定目标会话；`run` 顺序消费默认会话的命令流，在每次处理后调用观察者。失败返回错误并保留文本、选区和历史，流中的后续命令继续执行。前端提交命令、读取模型和观察更新，测试通过相同入口运行。

`InsertText` 按原字节替换选区，用于粘贴；`TypeChar` 和 `Enter` 执行语言感知输入；`Reindent` 显式调整一行。选区、语言配置和已有事务分别通过独立命令提交。输入和自动空白调整组成一个事务和一个撤销单位。

### 修订与更新

Document 的快照版本是文本修订，文本事务和历史恢复递增它。选区命令只修改目标会话，不生成文档修订或文本历史；语言配置变化单独递增 `config_generation`。事务的基准版本只校验文档文本，显式结果选区作用于目标会话。异步交互还需要校验自身的请求标识及会话上下文。

`EditorUpdate` 标明文档、目标会话、当前文本修订和配置代次，列出发生变化的会话选区，并在文本操作时携带 `DocumentUpdate`。后者包含操作来源、前后修订、实际修改和位置映射。普通编辑、撤销与重做使用相同的文档更新记录；未发生历史恢复的 Undo/Redo 不发布文档更新。

每次文档提交后，所有会话读取新快照。普通编辑采用发起会话的显式或映射后选区，其他会话通过精确变更映射自己的选区。文本和历史共享，选区彼此独立。

### 精确修改与历史

`compose_changes` 将两轮顺序修改组合回基准坐标，同时保留仍然存活的原始文本区间。组合后的事务可以包含多个修改；一次撤销不要求把它们合成一个连续替换范围。这样行首缩进和行尾输入之间未变化的代码，仍可正确映射其他光标、搜索位置或诊断位置。

`ValidatedChanges` 统一排序并校验范围、重叠、UTF-8 边界和结果长度，建立位置映射，不实际编辑文本。`EditorState::apply` 校验修改后生成 rope 并验证结果选区。公开组合接口建立第一轮结果以验证第二轮坐标；输入协调使用已经存在的临时快照，直接组合已校验的修改。原始区间不复制全文。`ChangeMap::map_tracked` 对替换范围内部的原始位置返回 `None`；边界仍按 Before/After 映射。该查询判断位置是否存活，不证明语义结果仍然有效。

文档历史记录精确的正向与逆向修改、所属会话及其操作前后选区。自动输入历史策略位于 editor，core 只接收事件类别与分组并执行历史算法。撤销与重做恢复历史所属会话的选区，其他会话按变更映射；所属会话关闭后，存活会话均按变更映射。`history_group` 只合并同一会话连续提交的同一组文本事务，选区命令、实际语言切换、会话关闭和历史恢复结束当前分组。新文本操作清空 redo 分支。

### 语言与分析

`language` 定义请求和建议的公共数据类型。`IndentAdvice::Set` 提供实际 tab/space 前缀和可选局部空白修改；`Preserve` 指定保护或换行继承策略；`Unavailable` 使用基础输入策略。editor 校验建议的行范围、字符边界和空白内容，再组合临时修改。语言模块负责语法判断，控制器负责提交与历史。

文本提交和历史恢复丢弃当前分析，选区变化复用分析。C++ 策略切换只在 parser 配置改变时丢弃结构。输入准备使用克隆的语言会话，临时快照的分析不会覆盖文档缓存。缓存只保存结构分析，不保存缩进结果。

控制器同步执行，不执行文件 I/O 或等待后台任务。`files::Workspace` 管理多文档与文件路径注册，通过独立文件服务完成读取、快照写入与结果确认，见[文件服务与文档生命周期](files.md)。模块所有权与请求状态约束见[架构边界契约](contracts.md)。后台调度和语言交互结果继续沿用文档标识、文本修订、配置代次与请求有效性检查。

## C++ 分析与输入操作

本节描述当前实现。目标查询与输入协调边界见[交互缩进设计与契约](indentation.md)；现有返回字段尚不是稳定扩展协议，求解规则限定为语言内部实现。

`parse_snapshot_with_options` 共享快照文本，并使用 `CppRules.parser_options()` 建立完整词法与结构分析。`parse_snapshot` 是默认 parser 配置的便捷入口。结构节点只通过只读接口访问，记录父子关系、token 范围、缺失 token 与不完整状态。分析同时保存使用的 parser 配置；调整缩进宽度可以继续查询同一结构树，调整宏分类必须重建分析。递归深度有上限，过深或受损输入进入消耗 token 的恢复路径。

格式分析保留完整 token 流和 `Vec` 中的轻量结构记录。`parser.rs` 管理扫描与容错状态，`syntax.rs` 提供只读结果和共享的格式事实查询。分析完成后建立 token 所属结构索引；括号组、宏控制头、直接逗号和构造函数冒号的判断由分析结果统一提供，缩进与表达式重放共用。

token 所属结构按半开的 token 范围确定，零宽缺失节点不拥有 token；插入位置查询可以落在结构边界或空白处，具有独立含义。节点和 token 下标仅对所属分析结果有效。预处理分类限制在指令的逻辑行内，分支消费、退出作用域和 extern 声明头使用明确状态。

`compute_indent` 接收已编译的 `CppRules`，校验分析与快照文本、parser 配置一致，再返回结构列、固定续行列、目标列、实际空白字节、结构角色和锚点。raw string、跨行注释及配置为 whitespace-sensitive 的宏内容受到保护；词法保护优先于 DisableFormat。预处理的 AfterHash 策略可以返回额外的局部间距修改。

`editor::enter` 先对选区替换后的文本做词法检查，普通换行仅在换行后的临时状态上做完整结构分析并查询缩进，生成指向原状态的事务。空括号展开候选额外校验换行前的结构关系。代码新行已有的前导空白由计算结果替换；字符串内部换行保留右侧字节。括号之间展开、行首空白和光标位置属于同一次操作。`editor::type_char` 仅在已提交字符实际形成相应标点 token 时触发调整，字符串、注释和组合标点内部的字符保持普通输入行为。访问标签、case 标签和闭合 token 的缩进变化与该字符一起撤销；粘贴应直接构造文本事务。

`editor::reindent` 修改指定行的前导空白及必要的预处理关键字间距。结构、固定续行与对齐列分别交给空白生成器，`IndentWidth` 与非零 `TabWidth` 独立配置。

## 存储与性能边界

文本存储采用 Ropey 1.6。启用 SIMD，行分隔识别为 LF/CRLF；单独的 CR 和 Unicode 行分隔字符作为普通文本保留。快照共享 rope；文本事务按范围从后向前更新，使全部修改继续使用同一基准坐标。UTF-8 字节到 Ropey 字符偏移的转换集中在存储层。读取逻辑行和校验字符边界使用 rope 的索引，空文档和末尾换行后的空行均保留。

`len_bytes`、`is_char_boundary`、`chunks` 和 `byte_slice` 提供长度、边界、分块遍历及零复制范围读取。`line` 返回 `Cow<str>`，在行跨 chunk 时只复制该行。`text` 是连续文本兼容接口，首次访问会生成完整 `Arc<str>`，同一文本快照上的后续访问和 parser 输入共享该缓存。选区变化共享已有存储，文本变化生成新的缓存入口。

撤销与重做历史保留 rope 和选区，不持有可重新生成的全文缓存。调用者显式持有的旧快照或分析结果仍拥有其文本，生命周期由调用者控制。当前 parser 和部分语言编辑操作仍通过连续文本执行，首次读取存在全文复制成本；core 的普通事务与分块读取不依赖它。

当前分析采用完整词法和结构分析，表达式续行重放限制在 4096 个 token 的区域内。当前文档缓存复用完整分析；后续局部重分析和检查点需要与完整结果进行差分验证。字符簇导航、基本编辑、搜索与文件重新加载已通过命令接入，见[编辑命令与无 UI 工作流](commands.md)。多选区与增量分析继续在这些接口上扩展。

## 验证方式

命令循环测试检查独立会话、跨会话映射、所属会话关闭后的历史恢复、配置代次和原子失败。变更组合测试通过随机 UTF-8 编辑与顺序执行对照；分组历史测试检查全部撤销和重做后的检查点。核心测试检查 UTF-8 范围、映射边界、历史分组和状态版本。语言测试检查 Enter 与输入轨迹、条件编译分支恢复、实际布局续行、空白字节、选区和撤销。

词法流应连续覆盖输入，根节点覆盖完整 token 流，子节点范围有序且属于父节点。结构语料的全部字符前缀、随机 UTF-8 输入和深度嵌套用来检验容错与终止。

在 release 构建中运行独立于 parser 的编辑轨迹：

```sh
cargo build --release --example core_edit_trace
/usr/bin/time -v target/release/examples/core_edit_trace 256
```

轨迹在约 1 MiB 文档的开头、中间和末尾插入，保留撤销历史并验证全部撤销后的内容。`edit_us` 只计事务提交阶段；进程峰值内存包含初始文本、结束校验和撤销。C++ 解析与缩进需使用单独的轨迹测量。
