# 交互层与搜索会话

交互层管理输入组件和功能会话，并输出 Application 事件。编辑核心拥有文档、编辑选区、位置映射和历史；终端 Host 转换平台输入、执行事件及文件任务，并绘制交互状态。

## 输入路由与命令循环

前端将平台事件转换为 `UserInput`：规范化按键、完整粘贴文本或未识别输入。`KeyStroke` 保存按键、Control/Shift、未支持修饰键标记和释放标记；重复按键与按下使用相同绑定。终端尺寸变化由前端处理，不进入命令解析。

`Layers::route_input` 是用户输入入口。存在模态层时，只解析该层的操作；模态层消费或阻止输入后，不再解析文档快捷键。确认或取消关闭模态层也不会把同一个按键再次交给文档。没有模态层时，内置绑定解析为 `interaction::Command`，粘贴解析为一次文本插入，再通过 `Layers::execute` 执行。

`interaction::Command` 表达编辑、打开、保存、搜索、文件 picker、关闭、切换视图和退出等操作；`editor::Command` 表达文档与编辑会话操作。其他调用入口可直接使用 `Layers::execute`，与键位入口共用目标解析和安全检查。活动模态层阻止直接调用应用命令；会话确认通过自身的事件输出完成。命令在调用时解析活动视图；另存为会话建立后保持目标文档。前端显式提供文件 picker 的根目录，交互层不读取进程工作目录。

执行返回 `Response`，包含有序 Application 事件、picker 任务、重绘、退出和状态消息操作。消息操作分为保留、清除、替换；组件输入和文档粘贴保留已有消息，显式应用命令清除或替换消息。Host 执行每个事件后，必须先将对应更新交给 `Layers::observe` 并处理后续响应，再执行下一个事件或接收下一次输入。文件和 picker 完成事件也遵守同一 owner thread 更新规则。

没有绑定且没有模态层的输入返回 `Pass`；当前终端 Host 忽略这类输入。没有活动视图时，需要视图的命令安全地不产生事件；创建文档、打开路径和文件 picker 仍可使用。

## 输入与组件

`TextInput` 保存单行文本和有方向的 UTF-8 字节选区，通过公开操作维持 grapheme 边界。插入、粘贴和删除作用于整个选区；普通左右移动先收起已有选区，扩展移动保留锚点。按词操作使用 Unicode word 边界，空白和标点作为分隔。

每次输入返回 `InputUpdate`，分别报告文字和选区变化。文字变化触发业务查询，单独的选区变化只请求重绘，无变化操作不触发查询或重绘。同长度替换仍是文字变化；替换成完全相同的文字只可能改变选区。插入与粘贴过滤控制字符，过滤后为空的输入保留原选区。确认、取消和业务操作由会话处理。

`Layers` 管理编辑视图上方的一个模态交互层，包括打开、另存为、跳转、离开文档确认、搜索、替换和文件 picker。活动层通过 `active()` 只读访问；进入或替换使用 `enter`，取消关闭使用 `close`，确认由输入处理入口完成。这些操作统一处理此前会话的恢复事件与任务取消，Host 必须执行返回的效果和事件。模态键位转换为平台无关的 `Input`。`Layers::handle` 在一次调用内完成路由与会话处理，返回 `InputResult`：

- `Pass`：没有模态层，交由编辑视图处理。
- `Blocked`：模态层阻止输入继续传播，当前状态没有变化。
- `Handled`：返回 `Response`，分别描述 Application 事件、重绘和退出请求。

模态层不识别的按键也会被阻止，避免输入落入文档。离开文档的确认只有显式丢弃选择才允许丢弃；回车和取消保留文档。修饰键由前端规范化，交互层的绑定解析统一校验组合，未配置的组合及按键释放不会提交、取消或修改输入。组件展示返回文字、字节光标及选区范围，终端布局负责转换为屏幕单元、裁剪和选区高亮。宽 grapheme 的光标位置与选区显示使用同一套布局计算。

另存为提示绑定目标文档，切换活动视图不会改变保存目标；目标文档关闭时，提示也结束。模态层结束后输入重新归编辑视图所有。

## 内置帮助

编辑区的 `F1` 打开只读帮助页，方向键、PageUp/PageDown 与 Home/End 浏览内容，F1、Enter 或 Esc 返回编辑区。帮助不修改文档、选区和编辑视口，并阻止编辑命令传播。前端提供可见行数，帮助组件只维护首个可见行。

`--help` 与内置帮助使用同一份快捷键说明；编辑区没有状态消息时显示常用键提示。替换确认同时提供 F4 和 Ctrl-Enter，F4 可用于不能区分 Ctrl-Enter 的终端。

## 关闭、退出与重新加载

`Ctrl-W` 关闭当前文档，`Ctrl-Q` 退出应用，`F5` 从磁盘重新加载。干净文档直接执行；未保存文档进入绑定文档的 `ExitSession`，明确提供保存、丢弃、取消。提示显示目标文件和将要进行的操作；`s` 保存，`d` 或 `y` 丢弃，`c`、Esc 或回车取消。未命名文档保存时继续请求路径；未命名文档不能重新加载。

选择保存后等待该文档的保存结果，不会提前关闭或退出。Host 必须在更新中观察保存请求的目标版本，并在 Application 返回错误时调用 `application_failed`。写入失败或路径预检失败恢复可重试的对话；成功但存在新编辑时重新请求决定。等待期间取消只取消离开流程，已经提交的保存继续完成。已有保存任务时不启动新的关闭、重新加载或退出流程。

退出按当前文档集合逐个询问，包括没有活动视图的文档。丢弃决定绑定对应文本版本，后续新编辑需要再次询问；中途取消不会删除已选择丢弃的文档，之前成功的保存仍有效。所有决定完成且没有待处理保存时才输出退出请求。关闭单个文档的丢弃立即关闭该文档；重新加载的丢弃明确授权用磁盘内容替换本地内容。

## 内部剪贴板

Application 拥有一个跨文档共享的内部剪贴板；系统剪贴板和终端粘贴独立于此状态。`Ctrl-C` 复制、`Ctrl-X` 剪切、`Ctrl-V` 粘贴。存在选区时复制或剪切选区，否则操作光标所在整行，保留原来的换行字节。空行末尾没有可复制内容时保留此前剪贴板。

复制保留文档、选区和历史；剪切在事务成功后才替换剪贴板，并将光标放到删除范围起点。粘贴在光标处插入或替换选区，作为一次独立的可撤销编辑。撤销恢复文档与选区，不改变剪贴板。模态层阻止这些文档命令；终端 bracketed paste 仍可直接输入到当前组件。

## 导航与选择

文档中的 `Ctrl-Left/Right` 按 Unicode 单词移动，`Ctrl-Backspace/Delete` 删除到前后词边界；已有选区时先删除选区。单词边界与输入组件采用相同规则，标点和空白是分隔符，跨行操作保留 grapheme 边界。查询逐行读取 rope，不生成全文字符串。`Ctrl-A` 全选。选区存在时 Tab 缩进所选行，Shift-Tab 反缩进，选区与事务一起映射；选区终点恰好位于下一行开头时不包含该行。没有选区时 Tab 按文档的 tab/space 策略插入缩进。

`PageUp/PageDown` 移动一个视口减一行，保留目标逻辑列并同时移动视口；Shift 扩展选区。前端通过 `set_page_rows` 提供编辑区可见行数；零或一行视口仍至少移动一行。core 只理解指定行数的垂直移动。

`Ctrl-G` 打开 `line[:column]` 提示，行列从一开始，列使用包含 tab 和宽字符的逻辑列。越界位置限制到文档或行尾，非法输入保留提示供修改；取消不改变选区。提示绑定创建时的视图，视图关闭或焦点切换时结束。

## 搜索生命周期

`SearchSession` 绑定一个视图，保存原选区、原视口、查询和搜索结果。查询变化从会话开始时的光标位置搜索；前后导航从当前匹配继续并环绕。匹配结果保存文档版本、匹配数量和当前范围，复用核心的 rope 快照字面量搜索，不保存完整匹配列表。

预览通过 `SetSelection` 命令显示当前匹配。空查询或没有匹配时恢复原选区与视口。确认将查询写入编辑会话，供后续查找使用；取消保留此前已确认的查询，并恢复原选区与视口。搜索不修改文本，也不生成文本撤销记录。

原选区与视口使用 `DocumentPosition` 保存。Host 必须按顺序将每个成功的 Application 更新交给 `Layers::observe`，包括其他视图对同一文档的编辑。选区端点采用核心选区映射的方向与关联规则；文档修改后重新计算匹配，不映射旧匹配范围。缺失更新导致过期版本错误，不会将旧坐标应用到新文本。

视图关闭时结束搜索。焦点切换时取消搜索并恢复原视图状态，保留新的活动视图。控制器输出的事件必须依次执行，每次执行的更新也必须交回交互层。

文档内搜索同步扫描当前快照，逐次查询的内存开销不随匹配数量增长。大型文件的输入延迟需要另行测量；项目搜索的任务调度、取消和异步结果契约在接入数据来源时建立。

## 搜索替换

`Ctrl-R` 建立绑定当前视图的替换会话，复用 `SearchSession` 的匹配预览、位置映射与取消恢复。先输入查询，再输入替换文字，最后进入确认阶段；替换文字可为空。查询与普通搜索一样使用区分大小写的字面量匹配。

确认阶段的 `Enter` 替换当前匹配，`F4` 或 `Ctrl-Enter` 替换整个文档中的所有匹配，`F3/Shift-F3` 选择前后匹配。替换完成后关闭会话；每次确认是一个可撤销事务。替换文字不会作为新的查询，也不会在输入过程中写入文档。任一阶段取消都恢复进入会话前的选区与视口；视图关闭或焦点切换时使用同一生命周期规则。文本更新后重新计算匹配，确认时由编辑控制器再次校验当前项。

## Picker 接入架构

文件 picker 由输入组件、候选列表状态、结果模型和功能会话组成。文件遍历和模糊匹配在后台执行，交互状态与确认动作在 owner thread 处理。

### 状态所有权

Picker 是组合交互层，包含输入、候选列表及可选预览。功能会话协调这些组件，候选导航和查询调度不进入 `TextInput`。

| 部分 | 拥有的状态与职责 |
| --- | --- |
| `TextInput` | 查询文字、输入光标与文字选区，报告文字或选区变化 |
| `CandidateListState` | 当前候选身份、用户是否主动选择、列表滚动位置；从结果模型读取行 |
| `PickerResults<T>` | 当前有效查询的有序候选、匹配数量、候选总量与截断信息；界面结果只有一个所有者 |
| `PickerSession` | 会话身份、有效查询、查询代次、结果模型与版本、加载状态、列表状态及生命周期；交互控制器据此输出任务和 Application 事件 |
| 候选来源 | 枚举文件或按查询获取候选，定义候选身份、匹配字段与业务数据 |
| 匹配适配层 | 根据候选集与查询过滤、排序并产生高亮范围，隔离实际模糊匹配库 |
| Host | 执行任务、回送带身份的结果、转换输入和绘制，只在 owner thread 更新交互状态 |

`CandidateListState` 不复制候选集合，也不根据列表下标确定业务对象。候选记录包含稳定身份、展示字段、匹配字段及类型化业务数据；文件候选的业务数据是 `PathBuf`。展示文字和实际路径分别保存，不能通过标签反推打开目标。显示名称相同的候选仍有不同身份，非 UTF-8 路径也必须保留实际路径字节。

候选身份在同一来源生命周期中跨查询保持稳定。跨来源组合时加来源命名空间。列表下标由当前排序派生，排序变化不会改变候选身份。匹配适配层将库返回的索引转换为展示文字的 UTF-8 范围，渲染继续使用 grapheme 和屏幕单元布局。

### 输入归属

Picker 默认将文字输入焦点留在 `TextInput`。当前候选与输入光标是独立状态：移动候选不改变查询、文字选区或键盘焦点。候选导航是会话处理的语义动作，不是输入框的左右移动或按词移动。

输入路由顺序为：会话级确认、取消与候选动作；输入组件操作；阻止未识别输入继续传播。输入选区变化只重绘，文字变化才更新有效查询并调度匹配。结果到达和候选选择变化不重置输入框选区。

导航接口表达上一项、下一项、分页、首项和末项，并显式提供是否环绕。具体按键与绑定上下文由前端适配；输入框与候选列表不会分别争抢同一个原始按键。页面大小由布局提供，尺寸变化只调整可见行和滚动，不改变查询。

候选列表的选择是单选，键盘焦点与选择分别处理。以后增加预览交互时，由会话显式处理焦点变化；渲染不隐式转移焦点，也不启动查询。鼠标等未接入的输入仍由模态层阻止。

### 查询与候选来源

候选来源有两种执行方式：

- 候选集来源：文件和命令等先建立候选集合，再根据查询进行本地过滤。文件遍历与查询匹配是不同任务，连续输入不会反复遍历文件系统。
- 查询来源：项目文本搜索等按查询请求结果，查询变化取消旧请求。防抖由请求调度处理，输入框本身立即更新。

文件 picker 打开时后台收集指定根目录的文件，形成候选集后再匹配最新查询。遍历期间保持加载状态。当前会话复用这一集合；磁盘上的新增或删除在重新打开 picker 或更换来源后体现。查询匹配与文件发现都由任务执行层承担，不在绘制函数中推进。

遍历复用 `ignore`，尊重根目录内的 `.ignore`、`.gitignore` 和 Git exclude 规则；隐藏路径、符号链接和非普通文件不进入候选集。父目录与全局 Git ignore 配置不参与此来源。目录读取错误最多保留八条告警，根目录不存在或不是目录时返回错误状态。

模糊匹配复用 `nucleo-matcher`，使用路径评分、smart case 和 smart normalization。查询作为一个完整 fuzzy needle，不解释筛选操作符。匹配适配层将库的 grapheme 索引转换为 UTF-8 展示范围；排序依次比较分数、展示文字、实际路径和身份。只为有界的展示结果生成高亮，不保存全部匹配行。

查询代次在有效查询变化时立即递增，早于防抖或任务启动。即使输入从 A 变成 B 又变回 A，也不能接受第一轮 A 的结果。当前文字即查询；候选筛选语法以后由查询解析器定义。

### 后台结果与资源契约

候选任务属于交互会话。`Response.effects` 返回 `PickerEffect`，后台完成以 `PickerCompletion` 回到 owner thread。`Layers::start_picker` 先结束此前的模态会话，再安装 picker；`picker_finished` 只将结果交给当前 picker。Host 的消息信封区分 Application 事件和交互事件，文档核心不接收临时 widget 结果。

请求携带会话身份、来源代次和查询代次。来源代次区分搜索根目录、数据来源的更换及失败后的候选集合重建。候选结果还携带数据修订和同修订内的结果序号。接收规则为：

1. 接收会话仍存在，且三项请求身份均与当前状态一致。
2. 数据修订不能早于已应用的修订；同修订内只应用更新的结果序号。
3. 数据与排序、高亮属于同一次结果快照，不能分别替换。

数据修订允许以后逐步更新候选集，而不把一次候选追加当成用户改写查询。较旧的部分结果可以在新结果尚未应用时展示；一旦应用更新修订，就不会退回较旧候选集。

新查询立即使旧查询候选失效。首轮清空有效结果并进入加载状态；没有有效候选时确认不执行动作，也不关闭会话。当前查询已有有效结果时，即使任务尚未完成，也可确认其中的候选。

取消用于停止计算，接收校验保证正确性。关闭会话立即使身份失效，再取消所属任务；迟到结果、错误和完成通知不能重新创建会话。任务取消须覆盖遍历、匹配和等待发送容量的过程。

`PickerRunner` 使用一个常驻 worker、一个最新待执行请求槽和容量为四的完成队列。默认最多收集 100,000 个文件，候选记录、Arc 计数器、字符串容量与候选向量实际容量的记账预算为 64 MiB，展示最多 1,000 个匹配。预算限制候选数据，不表示整个进程的内存上限；遍历器、匹配器和消息容器也有内存开销。查询超过 4,096 字节或 2,048 个 grapheme 时停止调度匹配并显示错误。这两个上限分别限制输入成本和匹配器 `u16` 分数的增长。预算检查先为候选对象及路径、展示文字的实际容量记账，再计算候选向量可保留的容量；向量按预算约束增长。达到候选集限制时报告截断；队列满时使用可取消的背压。匹配调度最多保留一个正在执行的请求和一个最新待执行请求，输入不会积累无限任务。Host 每轮按预算处理完成事件，保留处理键盘输入的机会。当前采用完整有序结果快照；每个文件查询发布一个快照，数据修订和序号均为零。接收端保留多快照的版本校验。Host 每轮分别处理最多八个 Application 完成事件和八个 picker 完成事件。

取消在遍历项之间、匹配候选之间和等待完成队列容量时检查。关闭与更换来源使旧任务失效；取消也清除待执行请求及缓存集合。Session 丢弃时通过取消标志和 Waker 唤醒 worker，即使没有另行发送取消效果，idle 缓存也会释放。大批候选的析构在调度锁外执行。Host 退出时关闭 worker 并回收线程。单次操作系统文件调用不由该取消机制强制中断。

单个候选任务 panic 时，worker 返回当前请求的错误快照并清空缓存与匹配器状态，后续查询可以重新计算。任务错误使当前候选集合失效并更新来源代次，防止重建集合中的候选编号与此前身份混用。完成通道断开与暂时没有结果分别处理：断开报告一次 worker 失败，交互层清除候选并展示错误；下一个有效请求重建 worker。线程创建失败同样显示错误，不会停留在无反馈的加载状态。

### 选择与生命周期

选择保持由会话协调，规则与重新排序分开：

| 变化 | 选择处理 |
| --- | --- |
| 有效查询或来源变化 | 清除旧选择，首批有效结果默认选择排序第一项 |
| 同查询更新，用户尚未导航 | 默认选择当前最高排序候选 |
| 同查询更新，用户已主动导航 | 按身份保留所选候选，不随新结果插入而跳到另一对象 |
| 主动选择的候选消失 | 在旧位置附近选择有效候选；空列表清除选择 |
| 窗口尺寸变化 | 保留候选身份，调整滚动以显示当前选择 |

默认最高候选与用户主动选择是不同状态，不能仅凭下标判断。相同输入、候选集与排序策略必须产生确定的排序，分数相同时使用稳定排序字段，结果顺序不依赖线程完成顺序。

确认时从当前有效结果取得业务数据，文件 picker 输出 `Application::Open`。不让后台工作线程直接打开编辑视图。确认产生一次结果并结束会话；取消结束会话并恢复原交互归属。文件打开由 Application 记录独立的打开意图代次与焦点版本。只有最新成功发起的打开请求，且发起后没有焦点变化，才可在完成时激活视图。较旧请求仍可创建后台视图，但不能覆盖最新意图。取消或读取失败不会重新激活更旧请求；前置校验失败不会替换此前有效意图。

文件 picker 的列表预览不修改文档编辑选区。以后增加预览时，使用独立只读展示状态和独立请求身份，候选变化只触发预览请求。预览请求还校验当前候选身份，不能仅依据查询代次接受结果。

### 接入与验证顺序

候选列表位于 `src/interaction/picker/list.rs`；文件来源与匹配适配层分别位于 `source.rs` 和 `matching.rs`；`worker.rs` 执行有界后台任务。`PickerSession` 接入现有 `Layer`、`InputResult` 和 `Response`。当前保留明确的 Rust 类型与组件枚举，通过实际的第二个候选来源验证复用后再扩大扩展接口。

验证需要包含：输入光标与候选导航互不干扰；同长度查询替换；同名候选确认；排序变化后的主动选择保持；新查询加载时确认；A/B/A 查询及乱序结果；关闭后结果到达；来源更换；非 UTF-8 路径；容量截断、取消和背压；分页和尺寸变化。假任务执行器可控制完成顺序，交互测试不依赖真实线程的时序。

## 当前终端入口

输入框的默认操作：

- `Left` / `Right`、`Home` / `End`：移动光标；配合 `Shift` 扩展选区。
- `Ctrl-Left` / `Ctrl-Right`：按词移动；配合 `Shift` 扩展选区。
- `Ctrl-A`：全选。
- `Backspace` / `Delete`：删除选区或相邻 grapheme；配合 `Ctrl` 按词删除。
- 输入文字或粘贴：替换选区。

文件 picker 的默认操作：

- `Ctrl-P`：从进程当前工作目录打开文件 picker。
- 输入文字：模糊过滤文件路径；输入框编辑操作保持一致。
- `Up` / `Down`、`PageUp` / `PageDown`：移动候选与分页。
- `Ctrl-Up` / `Ctrl-Down`：首项与末项。
- `Enter`：打开当前有效候选；加载或空列表时保留会话。
- `Esc`：取消并将输入归还编辑区。

`Home` / `End` 继续操作输入光标，候选导航不改变文字选区。当前列表导航在边界停止；列表状态接口也支持显式环绕。

搜索入口：

- `Ctrl-F`：打开文档内搜索。
- 输入查询：实时预览并显示匹配数量。
- `F3` / `Shift-F3`：下一处 / 上一处。
- `Enter`：确认查询与当前位置。
- `Esc`：取消并恢复原位置。

确认后，编辑区的 `F3` 和 `Shift-F3` 继续使用已保存查询。当前搜索为区分大小写的字面量匹配。

## 验证

`cargo test --test picker` 验证候选排序与选择、模拟完成事件的版本校验、原生路径、真实文件来源、长查询限制、实际容量记账以及丢弃会话后的缓存释放；worker 单测验证取消可以结束完成队列背压，以及断开通道的报告与后续请求恢复。`cargo test --test application` 验证并发打开请求的完成顺序、取消和失败都不会覆盖最新意图。

`cargo test --test interaction` 验证搜索预览、导航、确认和取消、跨视图修改后的锚点映射、关闭与焦点切换以及模态输入隔离。交互模块的输入组件测试覆盖有方向选区、按词操作、等长替换、过滤后为空的粘贴，以及组合字符和 grapheme 合并后的光标位置。终端 Host 测试验证修饰键与释放事件、重绘通知、选区裁剪及 Application 接入。

`tests/command_loop.rs` 通过前端无关入口验证键位和直接命令的等价行为、模态焦点阻止传播、确认取消只消费一次、另存为目标绑定、picker 任务生命周期以及无活动视图的行为。终端适配测试验证平台按键、修饰键、重复、释放和粘贴的转换；现有 TUI 测试验证 Host 执行响应后产生的实际状态。

`cargo test --test workflows` 验证复制剪切粘贴、Unicode 导航、跳转、翻页和替换。`cargo test --test departure` 控制保存完成的时序，验证保存后关闭、取消等待、写入失败、新编辑、逐文档退出与重新加载保护。
