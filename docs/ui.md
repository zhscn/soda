# 终端界面

`tui` 模块把 Runtime 的只读状态画成一屏。它不持有交互状态：每帧从 Application、交互层和 Runtime 读取需要的内容，先应用视口跟随，再绘制。渲染使用 ratatui（crossterm 后端），由它比较前后两帧，只输出变化的单元格；编辑区的文本裁剪仍由 `layout` 按逻辑列和 grapheme 计算，与核心的列宽规则一致。

## 布局

自上而下：

```
 main.cpp ●  util.h  [untitled 3]                       缓冲区标签栏
   1 │ #include <cstdio>                                  行号栏 + 文本
  12 │ int main() {                                       当前行高亮
 COMMAND  src/main.cpp [+]          <space>  C++  12:5   40%   状态栏
:open src/                              open PATH · 1/2   消息行 / 输入行
▌ sub/                                                         候选（命令行打开时）
  main.cpp
```

| 区域 | 内容 |
| --- | --- |
| 标签栏 | 每个已加载文档一项，包括没有视图的文档；当前文档高亮，`●` 标记未保存。放不下时从左侧省略，保证当前项可见。终端不足 4 行时省略。 |
| 行号栏 | 第一格是行标记（`flag-lines`）；右对齐行号，至少 3 位，随行数加宽；当前行号和整行使用高亮背景。窗口过窄时省略。行数按 Vim 的算法：末尾换行之后不算一行，`a\n` 只有一行；只有光标在那里时（Insert 中在没有末尾换行的最后一行按回车）才显示。 |
| 状态栏 | 左侧是模式标签（NORMAL、INSERT、VISUAL、V-LINE；有交互层时显示 COMMAND、SEARCH、REPLACE、SAVING、HELP）、相对文件根目录的路径、`[+]` 与保存中标记；右侧是未完成的按键、外部命令运行状态、语言、行:列和位置百分比。 |
| 消息行 | 最近的消息，没有时留空；启动页列出基本按键。搜索、替换和保存等待在这一行显示输入与光标。 |

编辑区文本按语法着色，分类与配色见[语法高亮](syntax.md)；状态栏显示的语言名来自高亮所用的语言（C++、Rust、TypeScript 等，未识别时为 text）。

## 窗口

编辑区由 Application 的窗口树划分（`application/windows.rs`）：
- 叶子是窗口，每个窗口显示一个视图；不在树中的视图仍然打开，只是隐藏。
- 分支按行（上下）或按列（左右）平分空间。在同方向上再分屏会增加兄弟窗口而不是嵌套，所以连续分屏的窗口大小相同。左右相邻的窗口之间留一列画分隔线。
- 有多个窗口时，每个窗口顶部有一行标题，显示文件路径和未保存标记，当前窗口高亮。行号栏按各自文档的行数计算。当前行高亮和终端光标只出现在当前窗口。
- 视口跟随只作用于当前窗口；其他窗口保持各自的视口，随编辑映射。

焦点规则：
- 聚焦一个已在窗口中的视图，就切换到那个窗口。
- 聚焦隐藏的视图（`buffer`、打开文件、新建文档），会在当前窗口里替换原来的视图，原视图转为隐藏。
- 关闭视图或文档后，失去视图的窗口改为显示最近用过的隐藏视图；没有可用的隐藏视图时，窗口关闭。
- 只有一个窗口时，这些规则与没有窗口树时完全一样。

方向切换在一个虚拟的正方形区域里计算窗口位置：在该方向上与当前窗口有重叠的窗口中，取最近的一个；距离相同时取与当前窗口上边或左边对齐最近的。

鼠标点击窗口会先聚焦它；滚轮滚动指针下的窗口。滚动非当前窗口时不移动它的光标，之后聚焦它时视口会回到光标处。

**侧窗。** 窗口树之外还有底部和右侧两个侧窗，参照 Emacs 的 side window：
- 底部侧窗占满宽度；右侧侧窗占底部侧窗以上的高度，与分屏窗口之间留一列分隔线。
- 侧窗按给定的行数或列数显示，但最多占一半空间；只剩侧窗时占满编辑区。
- 侧窗不能再分屏。可以关闭，`only` 也会关掉它们，方向切换照常进出。
- 侧窗失去视图时直接关闭，不会改为显示别的隐藏视图。

**显示规则。** 参照 Emacs 的 `display-buffer-alist`，把“显示什么”和“显示在哪里”分开，但只做声明式的一小部分（`application/display.rs`）：
- 按文档种类匹配，而不是名字正则。普通文档的种类是 `file`；scratch 文档按名字去掉星号，`*grep*` 的种类是 `grep`。
- 规则只在文档还没显示时起作用；已显示的文档直接切换到它所在的窗口。
- 配置写法是 `display KIND PLACEMENT`，可以写在配置文件里。

| 位置 | 行为 |
| --- | --- |
| `same` | 当前窗口。当前窗口是别的种类的侧窗时，按 `other` 处理。这是默认规则。 |
| `other` | 最近用过的另一个分屏窗口；没有时把当前窗口上下分开。 |
| `auto` | 已有侧窗时替换它的视图，大小不变。否则看最大的分屏窗口，参照 Emacs 的 `split-window-sensibly`：宽度不少于 150 列，且大于高度的 2 倍（字符高约为宽的 2 倍）时用右侧侧窗，占一半宽度；其他情况用底部侧窗。`grep`、`run`、`messages` 和扩展写入的结果文档（`soda.results`，如 LSP 的引用列表）默认使用它，已有 `display` 规则的种类按规则。位置在文档显示时决定，之后改变终端大小不会移动它。 |
| `bottom [ROWS]` | 底部侧窗，默认 12 行；替换侧窗中原来的视图。 |
| `right [COLUMNS]` | 右侧侧窗，默认 60 列。 |

因为 `same` 的这条例外，在底部结果列表里按回车打开文件时，文件会出现在上面的分屏窗口里，结果列表保持不动。

编辑区的行数是终端高度减去标签栏、状态栏和消息行。翻页使用当前窗口的文本行数；帮助与命令行候选按整个编辑区计算。视口跟随使用当前窗口去掉行号栏后的文本宽度。

## 浮层

浮层画在编辑区之上，使用圆角边框，不改变编辑区布局。

**命令行** 和搜索一样在状态栏正下方输入。有候选来源的参数位（命令名、路径、文件、缓冲区、选项、选择项）会在输入行下面列出候选，并把状态栏连同输入行一起往上推，覆盖编辑区底部，编辑区本身不改变高度，视口不会跳动。候选区高度固定（最多 10 行，编辑区较矮时相应减少，至少留一行文本），候选不足时留空；KEYS、shell 命令这类自由文字没有候选，命令行只占消息行。选中项带左侧标记和背景；匹配到的字符用橙色粗体，命令说明等次要文字用暗色。输入行右侧依次显示当前命令和参数说明（例如 `open PATH`）、命令行的问句（`unsaved src/a.cpp`）、加载状态和选中项序号；放不下半行时先省略参数说明。有错误时右侧只显示错误。光标在输入行。

**按键提示** 在多键绑定的前缀之后出现（例如按下 `<space>`），位于编辑区右下角，按列列出下一个键和命令说明；继续较长序列的键显示为 `+键`。按键在键位表中解析，提示只读取同一张表，用户绑定会立刻反映出来。

**帮助** 占满编辑区，内容可滚动；可见行数是编辑区高度减去边框。

没有打开的文档时，编辑区居中显示常用入口。

## 空白与列宽

- `wrap`（默认关）：长行折成若干屏幕行，不再水平滚动。断行点在一行内最后一个放得下的空格之后，空格留在上一行；一个词比整行还宽时在行尾断开，宽字符不跨行。续行的行号栏留空。视口的锚点可以落在长行中间的某一屏幕行，所以比整屏还高的行也能跟随光标；滚轮按屏幕行滚动，鼠标点击和跳转标签按屏幕行定位。Vim 的 `j`/`k` 和翻页仍按逻辑行计算（没有 `gj`/`gk`），长行很多时一次翻页可能越过不止一屏。
- `show-whitespace`（默认关）：制表符的第一格显示 `»`，行尾的空格显示 `·`，都用暗色；行内的空格保持空白。tab 与空格混排的缩进因此一眼可见。
- `ruler`（默认 0，即不显示）：给第 `ruler` 列之后的第一列加底色，与 Emacs 的 `display-fill-column-indicator` 相同。只在有文本的行上绘制，水平滚动后列不在窗口内时不显示。
- clang-format 的 `ColumnLimit` 通过 `%val{column-limit}` 读取，例如 `hook open .*\.(cpp|h) set-local ruler %val{column-limit}`；没有配置时为 0。

## 键盘

启动时查询终端是否支持 kitty 键盘协议；支持时开启 disambiguate 模式，退出（包括 panic）时恢复。这样 Ctrl-Enter、Ctrl-Backspace、Ctrl-I 与 Tab、Ctrl-[ 与 Esc 都能区分，`<c-ret>` 这类绑定才会生效。不支持的终端保持传统编码，这些组合键收不到或与基本键合并。协议用小写字母加 Shift 报告大写字母，前端把它规范成大写字母，与传统编码一致。

## 鼠标

启用鼠标捕获。`mouse` 模块用当帧的区域划分解析事件：标签栏中的点击按标签位置找到文档；编辑区中的点击和拖动由 `layout::offset_at` 按视口顶行和水平滚动列换算成字节偏移，点在行号栏时取行首；滚轮由 `layout::scroll` 计算新的视口，必要时给出光标回到可见区的位置。行为见[交互层](interaction.md#鼠标)。

## 主题

内置一套真彩主题，深色与浅色两个变体。`COLORFGBG` 报告浅色背景时使用浅色变体，否则使用深色。`COLORTERM` 为 `truecolor` 或 `24bit` 时输出 24 位颜色，否则换算为最接近的 xterm 256 色。主题设置整屏背景，不依赖终端自身的配色。

光标形状跟随模式：Normal 和 Visual 为方块，Insert 和所有输入为竖线。

## 测试

`layout` 的单元测试覆盖裁剪、宽字符、选区、视口跟随、软换行的断行与定位和输入行滚动。`view` 的测试用 ratatui 的 TestBackend 渲染整屏，检查标签栏、行号、状态栏、按键提示、命令行和帮助的组成。
