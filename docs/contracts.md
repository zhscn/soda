# 架构边界契约

编辑状态只由所有者通过明确入口修改。查询、编辑规划、文件 I/O 与结果应用分开执行，模块之间传递快照、建议、命令或带标识的结果。公开能力按工作流定义，内部算法保持私有。

## 模块职责

| 模块 | 拥有的状态 | 修改入口与输出 |
| --- | --- | --- |
| runtime::Runtime | Application、交互层、消息与后台任务 | 统一处理输入、命令、事件、错误、完成结果和视口反馈；对外只读查询 |
| core | 不可变文本与选区、历史算法 | 校验事务、建立映射、生成新快照；不依赖语言和文件 |
| editor::Document | 共享文本、历史、语言会话与分析缓存 | 控制器提交和历史恢复，输出 DocumentUpdate |
| EditorSession | 独立选区、期望列与搜索状态 | 选区命令，或文档提交后的映射 |
| editor::Editor | 文档模型与输入历史策略 | 接收命令、查询语言、原子提交并输出 EditorUpdate |
| language / cpp / rust | 建议类型、语言规则与分析 | 只读分析与建议，不提交修改 |
| files::Workspace | 控制器集合、FileState、路径与请求注册、结果队列 | 文件生命周期与结果确认，借出 `Editing` 句柄 |
| files::FileService | 配置选项与文件名到语言的映射 | 执行读写请求，不修改编辑模型 |

`Editing` 提供命令执行、会话管理和语言查询，不能替换控制器或改变文件绑定。工作区是控制器的唯一所有者，路径变化不改变文档身份。

## 文本与历史

- 事务范围指向同一基准快照，显式选区指向结果文本。任何校验失败时，文本、选区和历史都不变。
- 选区变化不推进文本修订；语言配置有独立的 `config_generation`；文件元数据只在工作区。
- 组合与映射只保证位置，不证明语义分析仍然有效。跨命令保留的位置使用 DocumentPosition，校验文档身份与修订（见[坐标契约](coordinates.md)）。
- `History<Owner>` 是唯一的历史算法。core 的单会话适配器使用单一 owner，文档以 SessionId 为 owner；会话选区的恢复与映射由文档控制器协调。恢复校验成功后才移动条目，净效果为空的恢复也产生新修订。

## 文件请求状态

### 读取

| 状态 | 允许的行为 |
| --- | --- |
| 已注册 | 执行请求，或通过 OpenId 取消 |
| 执行中 | 可以取消注册；结果仍须校验注册 |
| 已完成 | `finish_open` 应用有效结果；丢弃结果则取消注册 |
| 已取消 | 拒绝后续结果；新请求使用新标识 |

读取结果与原请求绑定。文件服务无权注册文档，取消或过期的结果不能创建文档。

### 保存

| 状态 | 允许的行为 |
| --- | --- |
| 已准备 | 捕获快照并预留路径；显式取消或 Drop 排队取消 |
| 执行中 | 保持预留；文档仍可编辑 |
| 已完成 | 显式确认，或 Drop 把完整结果排队回原工作区 |
| 已确认或失败 | 记录实际写出的内容或保留原基线，释放预留 |
| 栈展开中断 | 核对磁盘与请求快照，再确认或报告中断 |

保存请求和结果都只使用一次，确认按文档身份、请求标识与目标路径进行，且只在原工作区。确认不覆盖当前文本和选区，当前内容与已写出内容分别管理。

请求、结果与工作区之间通过结果路由连接。Drop 只排队通知，不执行 I/O，也不修改编辑状态；工作区的 poll 或文件生命周期入口在所有者线程应用通知，产生的更新与错误（附带文档身份）保留给宿主消费。

## 前端与运行时

前端通过 `Runtime` 提交输入、命令和事件，不按固定间隔轮询：它等待输入、唤醒或 `Runtime::deadline()` 给出的时间，然后调用 `poll`。后台线程把结果交给 owner thread 的通道后调用 `crate::wake::wake()`，唤醒前端注册的函数（图形前端是 winit 的 `EventLoopProxy`，终端前端是读终端线程与主循环共用的通道）。`deadline` 覆盖不由线程送来的工作：一次 `poll` 没取完的结果、idle hook、Lua 定时器、待发给语言服务器的修改、按键提示的消失。新增后台任务时两者都要接上，否则结果要等下一次输入才出现。

Runtime 按顺序执行事件，每个成功更新在处理下一个事件之前交给交互层。多事件响应在首个失败处停止，已提交的事件保持有效，后续事件和退出请求不执行。错误携带 `Operation` 身份，保存错误只作用于对应文档和保存请求。

文本区布局在 `screen`，与绘制方式无关：行是统一高度的文本行，水平方向用前端提供的 `Measure` 计量（终端是单元格，图形前端是像素）；tab 停靠、折行、inlay、水平滚动（`Viewport::horizontal_scroll`，单位同 `Measure`）、光标位置和从屏幕位置回到字节偏移按同一套规则计算。布局是只读投影，需要滚动时返回视口反馈，由 Runtime 经 Application 更新。隐藏编辑光标的模态层保留编辑视口。标签、窗口标题、状态栏和消息行的内容也在 `screen`，外观和位置由前端决定。前端划分区域、绘制、解析鼠标，并把各窗口的行数报告给 Runtime（翻页、侧窗与显示规则使用）；窗口树以行列为单位，图形前端按默认字体的单元格尺寸换算。会话的启动与收尾在 `host`，各前端共用：加载配置与保存的状态、捕获 panic，循环异常结束时把未保存文档写入恢复目录。

文件读写由 `files::FileRunner` 执行：两个 worker、容量 16 的任务队列和容量 16 的完成队列。提交不等待空位，被拒绝的请求经正常 Drop 路由取消并输出有身份的终态；worker 内的 panic 变为 `FileCompletion::Failed`。关闭时解除完成队列的背压，待执行任务取消，执行中的同步写入完成后 worker 才退出。Picker 有自己的单 worker 和有界结果队列。每次 `poll` 对文件、picker 和路径补全结果各最多处理八个，其余由 `deadline` 安排尽快处理。

直接使用 Application 或 Workspace 的调用者仍须消费更新并轮询 Drop 通知。后台语言、搜索与补全结果在应用前须校验文档身份、文本修订、配置代次与请求上下文。
