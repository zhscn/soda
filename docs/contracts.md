# 架构边界契约

编辑状态由其所有者通过明确入口修改。查询、编辑计划、文件 I/O 和结果应用分别执行，模块之间传递快照、建议、命令或已标识的结果。公开能力围绕实际工作流定义，内部算法保持私有。

## 模块职责

| 模块 | 拥有的状态 | 修改入口与输出 |
| --- | --- | --- |
| runtime::Runtime | Application、交互层、状态消息与后台任务 | 统一输入、命令、事件、错误、完成结果及视口反馈；对外只读查询 |
| core | 不可变文本与选区投影、内部历史算法 | 校验事务、建立映射、生成新快照；不依赖语言或文件 |
| editor::Document | 当前文本、共享历史、语言分析及文件元数据 | 控制器提交和历史恢复，返回文档更新 |
| EditorSession | 独立选区与共享快照投影 | 选区命令或文档更新后的映射 |
| editor::Editor | 模型与同步输入协调 | 接收命令、查询语言、原子提交并输出更新 |
| language / cpp | 建议契约、语言规则与分析缓存 | 只读分析和建议，不提交文档修改 |
| files::Workspace | 控制器集合、路径注册、请求注册和结果队列 | 文件生命周期与结果确认，返回编辑能力句柄 |
| files::FileService | 文件操作配置 | 执行不可变读写请求，返回结果或排队通知 |

`Editing` 提供命令执行、会话管理和缩进查询，读取模型使用只读引用。工作区是已注册控制器的唯一所有者；文件路径改变保持文档身份，编辑能力不能整体替换控制器。

## 文本与历史

事务范围指向同一基准快照，显式选区指向结果文本。版本、UTF-8 边界、重叠和结果选区校验失败时，文本、选区及历史均不改变。选区变化不推进文本修订，文件元数据与语言配置具有独立更新含义。

修改校验与 rope 编辑分别实现。内部已经校验的输入通过对应临时快照组合回基准坐标，保留存活的原始区间。组合与映射不证明语义分析仍然有效。文本与逻辑列采用[坐标契约](coordinates.md)中的独立单位，DocumentPosition 校验保留位置的文档身份和修订。

`History<Owner>` 是唯一的历史算法，实现组内组合、逆向修改、分支迁移和操作前后选区。core 单会话适配器采用单一 owner，文档采用 SessionId；前端会话的恢复及映射由文档控制器协调。历史恢复校验成功后才移动条目，净效果为空的恢复也产生新修订。

## 文件请求状态

### 读取

| 状态 | 允许的行为 |
| --- | --- |
| 已注册 | 执行请求，或通过 OpenId 取消 |
| 执行中 | 可以取消注册；结果仍须校验注册 |
| 已完成 | finish_open 应用有效结果；丢弃结果取消注册 |
| 已取消 | 拒绝后续结果；新请求使用新标识 |

读取结果与原请求绑定。文件服务没有注册文档的权限，取消或过期结果不能重新创建文档。

### 保存

| 状态 | 允许的行为 |
| --- | --- |
| 已准备 | 捕获快照并预留路径；显式取消或 Drop 排队取消 |
| 执行中 | 保持预留；当前文档仍可以编辑 |
| 已完成 | 显式确认，或 Drop 将完整结果排队回原工作区 |
| 已确认或失败 | 确认实际写出内容或保留原基线，释放预留 |
| 栈展开中断 | 核对磁盘与请求快照，再确认或报告中断 |

保存请求和结果都只使用一次。确认对象包括文档身份、请求标识与目标路径，结果的确认发生在原工作区。保存确认不覆盖当前文本和选区，当前内容与实际写出内容分别管理。

文件请求、结果和工作区之间通过结果路由连接。Drop 只排队通知，不执行 I/O 或修改编辑状态；工作区 poll 或文件生命周期入口在所有者线程应用通知。已应用通知的更新与错误保留供宿主消费，错误附带文档身份。

## 前端与运行时

前端使用 `Runtime` 进行输入、命令调用、事件提交和后台结果轮询。前端不按固定间隔轮询：它等待输入、唤醒或 `Runtime::deadline()` 给出的时间，然后调用 `poll`。后台线程把结果交给 owner thread 的通道后调用 `crate::wake::wake()`，唤醒前端注册的函数（图形前端是 winit 的 `EventLoopProxy`，终端前端是读终端线程与主循环共用的通道）；`deadline` 覆盖不由线程送来的工作：`poll` 一次没取完的结果、idle hook、Lua 定时器、待发给语言服务器的修改、按键提示的消失。新增后台任务时，两者都要接上，否则结果要等下一次输入才出现。Runtime 拥有 Application 与交互层，按顺序执行事件，每个成功更新在处理下一个事件之前交给交互层。多事件响应在首个失败处停止，已提交事件保持有效，后续事件和退出请求不执行。错误携带 `Operation` 身份，保存错误只作用于对应文档和保存请求。

文本区的布局在 `screen`，与绘制方式无关：行是统一高度的文本行，水平方向用前端提供的 `Measure` 计量（终端是单元格，图形前端是像素），tab 停靠、折行、inlay、水平滚动（`Viewport::horizontal_scroll`，单位同 `Measure`）、光标位置和从屏幕位置回到字节偏移都按同一套规则计算。布局是只读投影；需要滚动时返回视口反馈，由 Runtime 通过 Application 更新并观察。隐藏编辑光标的模态层保留编辑视口。标签、窗口标题、状态栏和消息行的内容也在 `screen`，外观和位置由前端决定。前端自己划分区域、绘制并解析鼠标，并把各窗口的行数报告给 Runtime（翻页、侧窗与显示规则使用）；窗口树以行和列为单位，图形前端按默认字体的单元格尺寸换算。会话的启动与收尾（配置、状态、panic、未保存文档的恢复）在 `host`，各前端共用。

Runtime 使用两个文件 worker、容量为 16 的任务队列和容量为 16 的完成队列。任务提交不等待空位，拒绝的请求通过正常 Drop 路由取消，并输出有身份的终态。完成队列背压可在关闭时解除；待执行任务取消，执行中的同步写入完成后才退出 worker。Picker 保持自己的单 worker 和有界结果队列。Runtime 每轮分别最多处理八个文件和 picker 完成结果。

直接使用 Application 或 Workspace 的调用者仍须消费更新和轮询 Drop 通知。后台语言、搜索与补全任务接入时，需要校验文档身份、文本修订、配置代次与交互请求上下文。
