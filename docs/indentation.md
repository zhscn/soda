# 交互缩进设计与契约

缩进能力的稳定边界是一次编辑操作：在确定的文档快照、插入位置和配置下，给出可局部应用的空白建议。语法树、启发式分类、续行栈及配置规则表属于语言实现内部；编辑内核只理解修改范围、空白、选区和版本。

本文定义目标契约。[编辑内核与接口](core.md)描述当前 Rust API；`CppRules` 提供只读行为策略，`IndentSlot` 限定为求解器内部表示；现有 `IndentDecision` 和输入协调接口继续按本文边界收敛。

## 1 职责与表示

| 层 | 输入与输出 | 所有者 |
| --- | --- | --- |
| 配置适配 | 完整 clang-format 配置 → 已校验、已解析缺省值的 C++ 策略 | 项目配置服务 |
| 语法分析 | 快照及语法配置 → token、结构和恢复信息 | C++ 语言模块 |
| 缩进求解 | 编辑位置、分析、策略及实际布局 → 空白建议 | C++ 语言模块 |
| 空白生成 | 列区间及 tab 策略 → 精确字节 | 语言无关的纯函数 |
| 输入协调 | 用户操作及语言建议 → 原子事务与结果选区 | 编辑操作层 |

配置策略描述用户选择的行为，例如 namespace 缩进方式、访问标签偏移、参数对齐及宏分类。它不描述分析器如何识别这些情况，也不要求每个行为对应一个树节点或规则槽位。外部选项的兼容拼写、继承和缺省值在配置层处理；具体代码位置的锚点在查询时解析。

`IndentSlot` 可以作为 C++ 内部降低重复分支的实现工具，但不是配置格式、插件协议或编辑内核接口。表达式状态机、结构树和规则表可以独立调整；调用者不能依赖槽位编号、节点种类或某个解析栈的排列。配置对象只读，风格变化通过替换策略对象生效。

分析器提供源范围、括号关系、结构完整性和局部歧义等事实。求解器根据这些事实和编辑位置决定结构基准、续行或对齐。两者可以共享语言内部数据，但不能让分析树保存由当前缩进宽度计算出的永久列值。实际列依赖文本和列度量策略，按需计算或使用带版本的缓存。

## 2 分析方法与参考边界

C++ 需要能处理未完成输入的局部分析。词法状态优先确定字符串、注释、预处理续行等边界；容错结构分析识别作用域和逻辑语句；按需分类处理模板、初始化列表、冒号及宏等歧义；续行求解重放实际布局。未知或恢复得到的结构保留可靠范围，查询只使用足够可信的锚点。

借鉴 clang-format 的职责划分和局部状态计算，保留用户指定的换行位置。借鉴 IntelliJ 在插入位置查询子项缩进、区分不完整结构，以及将缩进与对齐分开生成空白的设计。语言分析不要求先完成整个项目的语义检查。

CC Mode 的参考价值在于上下文覆盖、配置行为和编辑轨迹。语法符号列表、offset 回调和启发式解析状态不作为 Soda 的公共表示。C++ 内部仍然可以使用有界启发式，但每个启发式须有明确作用范围、失败路径及行为测试，不能成为调用者必须理解的协议。

空白行或两个 token 之间的插入位置可能没有所属语法节点。查询必须同时考虑前缀、后缀和未闭合结构，不能简单将“最近节点的缩进”作为答案。例如，在 `call(first,|second)` 中按 Enter，后缀仍属于参数列表；在 `class A { public:|` 后换行，需要查询成员插入位置。

预处理指令按逻辑行解析，反斜杠续行仍属于同一指令。指令体中的不完整括号不会吞并下一条指令或普通代码。条件分支允许在不同分支中打开或关闭代码块，也支持由两段 `#ifdef __cplusplus` 包围开闭括号的 `extern "C"`；这些都是格式结构，分析器不求值条件表达式。

表达式中的 lambda 体是嵌套代码块，不结束所在语句。体缩进一级、闭合括号对齐的基准对应 clang-format 的 NestedBlockIndent（`LambdaBodyIndentation: Signature`）：基准属于 lambda 所在的作用域，由在该作用域层级开始的续行重置为行首列，行首为条件运算符时取运算符后的列；嵌套括号从开括号处继承，`if`/`for` 条件从括号后的首个 token 开始。语句层级换行后带尾置返回类型的 lambda 按独立函数布局，基准保持语句缩进。

模板参数列表内的括号和嵌套参数列表是独立作用域，`>>` 同时结束两层列表。括号内的 `<` 按 clang-format 的启发式识别：同层出现二元 `&&`/`||`、出现条件运算符且 `>` 后不是 `(`/`{`，或 `>` 后紧跟字面量时视为比较运算符。续行重放中，块注释（如 `/*Arg=*/`）是普通 token，可以作为对齐锚点；行注释不参与布局，下一行从前一个代码 token 继续。不带花括号的控制语句体是独立的逻辑行，只有条件部分延续控制语句。

宏块分类保留原始 token 和源码范围。`MacroBlockBegin/End` 配置提供一般块边界；当前文件中可直接识别的对象式 `#define` 则保留更具体的结构：`namespace name {`、`extern "C" {`、`extern "C++" {`、`{` 和 `}`。定义按出现顺序生效，重定义及 `#undef` 更新分类。条件分支结束时只保留各分支一致的分类；没有 else 的条件还要与进入条件前的分类一致。文件级 `#ifndef NAME`、`#define NAME`、末尾 `#endif` 形式的 include guard 按透明包装处理。宏别名、参数替换、递归展开和其他复杂替换体需要显式配置，分类器不执行通用宏展开。

## 3 查询契约

以下是语义模型，具体 Rust 类型可以在实现时收敛：

```text
IndentQuery {
    snapshot                 // 文档标识与文本版本
    site                     // 目标行、插入点及本次操作产生的范围
    trigger                  // Enter / CommittedText / Reindent
    policy                   // 不可变有效配置及其版本
    budget
}

IndentOutcome =
    Set { prefix_plan, auxiliary_whitespace, evidence }
  | Preserve { reason }
  | Unavailable { reason }
```

所有位置属于请求快照的 UTF-8 字节坐标。`site` 指向用户意图已经应用、自动缩进尚未应用的临时文本，允许目标行没有 token。请求只读，不读取文件、不启动进程、不提交编辑。

`Set` 给出目标行前导空白的列计划。建议可以附带语法明确要求的局部空白修改，例如预处理指令中 `#` 后的间距；附加范围必须显式返回并由协调器检查。建议不能修改非空白 token 或扩散到未授权的行。

`Preserve` 表示语言明确要求保留该上下文的字节，例如 raw string 或 whitespace-sensitive 宏内部。协调器不再用普通结构缩进覆盖它。`Unavailable` 表示缺少可靠上下文、分析不可用或预算耗尽，协调器使用确定的基础输入策略。保护结果与计算失败具有不同语义。

证据可以记录使用的源锚点、可靠度和降级原因，用于测试与诊断。结构角色可作为诊断信息；调用者不能根据角色名再次实现一套缩进算法。结果携带的有效性标识须覆盖文本、语法配置、缩进策略和列度量策略。版本不匹配是无效请求或过期结果，不伪装成普通降级。

## 4 空白计划与混排

空白计划描述最终前导空白从第 0 列到目标列的连续区间。区间按用途区分结构、固定续行和对齐；负偏移和退格结果先裁剪到实际目标列。引用源锚点用于解释位置，空白生成器接收的是已经解析出的列和用途，不访问语法树。

三个用途不等同于三个必须逐项累加的偏移。例如访问标签可以低于成员基准；参数可以对齐到已有首项；已有不规则缩进可以成为局部基准。求解器负责产生有效、单调且无重叠的最终区间，空白生成器不负责修复语义决策。

列计算与字节位置分开。`IndentWidth` 是结构偏移，`TabWidth` 定义 tab stop，固定续行另有宽度。对于正整数宽度 W，tab 从列 c 前进到 `c + W - c % W`。对齐锚点使用原文本的实际列，不能把每个 tab 替换成 W 个空格再测量。

生成器按 `UseTab` 的有效语义判断哪些区间允许 tab；一个 tab 覆盖的整个区间都必须允许，且不能超过目标列。区间边界保留结构与对齐的区别，但不自动禁止横跨两个均允许 tab 的相邻区间。剩余列补空格，最终字节重算后的列必须等于目标列。

例如仅结构部分允许 tab，结构结束于第 8 列、目标为第 11 列、TabWidth 为 4 时，结果为 `"\t\t   "`。若结构结束于第 6 列，则结果为 `"\t       "`：第二个 tab 会跨过结构边界，因此采用空格。对纯行首空白以外的局部修改，生成器显式接收实际起始列。

列度量是语言编辑服务的共同约定，不由 TUI 或 GUI 临时决定。终端显示、GUI 字体布局与逻辑列分别转换；配置或度量规则变化必须使列缓存失效。

## 5 编辑操作契约

### Enter

1. 从基准状态确定选区替换、换行符和局部括号展开意图。语言可以建议展开匹配括号，协调器决定并限制修改范围。
2. 应用用户意图形成临时快照；分析该快照，查询新行及展开后需要调整的闭合行。
3. 校验建议范围，生成空白，计算最终选区。普通换行后的 caret 位于新行前导空白之后、原后缀之前。
4. 将临时修改组合为一个指向基准版本的事务。提交时再校验版本；换行、空白、括号展开和光标一次撤销。

临时坐标必须通过统一的编辑组合与位置映射转换，不能仅按换行长度平移所有建议。行中换行、选区跨行、同一位置的插入及额外空白替换都要使用同一组合规则。

raw string 内的 Enter 插入用户请求的换行，后缀保持原字节；普通代码在无法求解时沿用拆行前的行首空白。注释、普通字符串及受保护宏可以有独立输入策略，新增注释前缀等行为须由该策略显式建议。DisableFormat 下的 Enter 沿用行首空白，显式重新缩进保留原字节。

语言计算不可用时，用户输入仍按基础策略提交。事务版本冲突或范围错误则原子失败，调用方基于最新状态重新执行操作。后台分析结果供后续输入使用，不追加修改已完成操作或移动其光标。

### 输入、重新缩进与其他来源

| 操作 | 自动缩进范围与提交方式 |
| --- | --- |
| 已提交文本输入 | 先应用输入，再检查是否形成访问标签、case 标签、闭合符或指令；输入与当前行局部空白一起提交 |
| IME composition | 组合阶段只更新输入状态；最终提交的文本按已提交文本处理 |
| 显式重新缩进 | 修改指定行的前导空白及已声明的辅助空白；保护上下文保持原字节 |
| 粘贴 | 按文本事务插入原字节；单独的重新缩进命令按其范围契约执行 |
| 字面 tab | 插入 tab 字节，按 tab stop 计算结果位置 |
| 缩进增减 | 依据明确的列步长及空白策略修改选定行；不等同于插入 tab |

语言声明触发条件，输入协调器保证一次操作只执行一轮自动调整。自动生成的空白不会再次被当作用户输入递归触发。输入来源和逻辑编辑命令分开，前端按键绑定不进入语言求解器。

当前实现支持单选区。扩展多选区时，各输入意图使用同一基准版本，在统一临时快照上求解；同一行和重叠范围需要显式合并或拒绝，结果不能依赖光标遍历顺序。

## 6 缓存与验证

分析只有在源码内容和语法配置匹配时才可用于查询。文档可以保留上一份分析作为增量计算的基线；宏分类配置变化会清除它，缩进宽度变化可以复用结构。输入协调器隔离试算分析，并在事务成功提交后保留它；失败输入不替换文档分析。撤销、重做和重新加载也通过同一内容匹配规则重新分析。缩进结果还依赖有效策略、实际布局及列度量，不能仅按节点编号缓存。

增量词法扫描从修改前的独立换行 token 后重新开始，在未改变的后缀中遇到对应换行 token 后收敛。字符串、块注释和反斜杠续行内部不作为恢复点；未闭合 token 可以使扫描延伸到文件末尾。词法 token 和语法有意义的拼写保持一致时复用节点结构，否则从首个不同 token 及前一个有效 token 的归属节点向外寻找完整的 namespace、class/enum、函数、代码块或 case section。前一个有效 token 提供行尾空白中的逻辑归属，例如在 case 的最后一条语句后插入新行。

局部入口恢复祖先栈和 enum 上下文，保留未修改的前缀项，重放编辑位置及其前一项，再在可靠的旧项边界复用后缀。前一项也可能受新插入的 else、case 内语句或 class 分号影响，不能仅凭它原来的结束位置判定可复用。brace 容器的真实开闭括号必须保持不变；case section 保留完整标签，从冒号后重解析，并在下一标签、闭块或 EOF 处校验边界。新增标签改变 case 的兄弟归属，需要扩大到外层 switch。项之间以分号、闭括号或 enum 的逗号作为恢复边界。前后片段的节点和 token 索引重新映射，跨越修复区间的祖先范围和后续兄弟引用一并更新，索引不跨分析保持稳定。

局部区域可以位于条件编译分支、预处理重新打开的作用域或未闭合的外层作用域中，但区域自身必须完整，新旧 token 范围都不能包含预处理指令。区域内的项解析不会读取或修改条件帧，窗口之外的分支、缺失 token 和恢复信息整体保留。修复器不恢复条件帧，也不重放窗口外的指令；该路径依赖稳定边界与指令隔离，而不是条件表达式求值。

启发式重分类的括号组和自身不完整的区域选择更外层上下文。边界校验或重解析失败时依次扩大到可恢复的外层区域、顶层声明，最终回退完整解析。跨预处理指令、跨分支的窗口仍执行完整结构解析；外层未完成不必阻止内部独立区域的局部修复。

clang-format 的 `TokenAnalyzer::process` 每次扫描并解析格式结构，再由 affected-range 机制筛选行；范围格式化不等于跨编辑的局部重解析。

当前实现仍有完整源码物化、前后缀比较、token/节点数组复制及归属索引重建的线性成本，因此局部扫描和解析不构成端到端次线性性能保证。`CppSession::analysis_work` 报告扫描字节、重解析窗口的 token 数、复用节点数及完整回退原因。重解析统计包含失败尝试的窗口；冷启动的完整分析不属于回退。运行 `cargo run --release --example cpp_analysis_trace -- FILE TARGET 20` 可比较冷启动与连续不同替换后的分析耗时，TARGET 使用待修改的标识符。该 trace 不写文件，计时包含新快照的源码物化及一次第零行缩进查询。

差分测试比较完整与增量分析的 token、节点、宏分类、归属索引及逐行缩进建议，运行 `cargo test incremental --lib` 验证。

契约测试通过输入轨迹断言文本字节、caret、修改范围和一次撤销。重点覆盖选区替换、行中换行、空白新行、未闭合结构、现有后缀、配置切换、保护与预算降级。混排矩阵包含非整除宽度、空格后接 tab、负偏移和结构/续行/对齐边界。内部树形变化不应要求这些测试改变预期。

`cargo run --release --example indent_accuracy -- <文件或目录>` 对已按 `.clang-format` 格式化的源码逐行计算重新缩进建议，并与文件中的实际缩进比较，报告一致、不一致与保留的比例；语料应只包含 clang-format 输出无变化的文件。

`tests/clang_format_editor.rs` 将 LLVM `FormatTest.cpp` 中与行首缩进有关的例子改成实际 editor 命令测试。每个例子记录上游测试名、配置覆盖和带 caret 标记的预期文本；文件头记录上游版本。预期值来自上游排版例子，允许缩短标识符和省略无关语句，但必须保留影响缩进的上下文。用例不在运行时调用 clang-format，也不从当前求解器生成预期值。

Enter 路径删除标记所在行前的换行和前导空白，再通过 `Command::Enter` 恢复它们；Reindent 路径将该行前导空白替换为混合空白，再通过 `Command::Reindent` 修复。两条路径均检查完整文本字节、caret、撤销恢复和重做，并分别运行 LF 与 CRLF。输入保留文件末尾换行，使 Enter 可以识别文件的换行风格。运行 `cargo test --test clang_format_editor` 验证这组用例。

这些用例验证用户已经选择换行位置时的缩进行为。新增上游例子时，应显式选择目标边界，并记录所需配置；自动折行、整段重排和行尾空白对齐不能直接作为即时缩进的预期。受保护文本、未完成输入及输入标点触发调整继续由 editor 与 Enter 的专项测试覆盖。

- IntelliJ Community：`~/project/intellij-community`。`platform/code-style-api/src/com/intellij/formatting/{Block,ChildAttributes,Indent}.java` 提供插入位置、完整性及缩进抽象；`platform/code-style-api/src/com/intellij/psi/codeStyle/lineIndent/LineIndentProvider.java` 提供即时查询与保留语义；`platform/code-style-impl/src/com/intellij/formatting/IndentInfo.java` 提供缩进/对齐空白分离。这些是公开平台及语言实现的参考，CLion 的 C++ 行为另以编辑用例验证。
- Emacs C++ 配置：`~/.emacs.d/lisp/init-cc.el`。用于核对配置行为、tab/space 混排和上下文用例。
