# 文件服务与文档生命周期

`files::FileService` 执行同步磁盘操作：解析路径、读取文件、确定语言与配置、写入不可变快照，不修改编辑模型。`files::Workspace` 拥有各文档的控制器和 `FileState`，管理路径注册与读写请求，在所有者线程应用结果；`editor_mut` 借出 `Editing` 句柄（见[架构边界契约](contracts.md)）。同一文档的多个会话共享文件状态。

## 打开与文档身份

`Workspace::open` 返回 `DocumentId`。路径规范为绝对路径并解析符号链接；已打开的路径返回原文档，保留当前内容。另存或 `relocate` 改变路径不改变身份；关闭后重新打开得到新身份。

读取只接受普通文件和 UTF-8。开头的 UTF-8 BOM 记为文件元数据，不进入文本；LF、CRLF、单独 CR、tab、space 和末尾换行按原字节保留。无效 UTF-8、目录和读取错误返回 `FileError`，不注册文档。

异步打开分三步：`prepare_open` 对已打开的路径返回 `Existing(DocumentId)`，否则返回带唯一 `OpenId` 的 `OpenRequest`；`FileService::read_request` 产生 `OpenCompletion`；`finish_open` 校验请求注册后应用结果。`open` 是同步组合。

每条路径同时只有一个读取请求。`cancel_open` 在读取执行中也能取消注册，之后到达的结果返回 `StaleCompletion`；丢弃请求或结果会向原工作区排队取消。其他工作区或较早请求的结果不能用于当前请求。`FileService::read` 可以独立读取 `LoadedFile`，但不能用来注册文档。

| 入口 | 结果 |
| --- | --- |
| `new_document(language)` | 未命名文档；空时未修改，输入后未保存；首次保存须指定路径 |
| `new_scratch(name)` | 名为 `name` 的 scratch 文档（如 `*grep*`），PlainText，没有文件，永不算未保存；`scratch(name)` 查找它 |
| `open_or_create(path)` | 文件不存在时建立绑定该路径的空文档，即使为空也算未保存 |
| `finish_open` 读到文件不存在 | 同 `open_or_create` |
| `relocate(id, path)` | 跟随磁盘上的重命名：改绑路径、重新确定语言，已保存基线不变 |

文件服务不隐式创建父目录。尚未写出的路径由保存请求预留，防止另一个文档同时占用。

## 语言与配置

语言按文件名确定：先查 `map_language` 配置的完整文件名，再查最长的配置扩展名（以 `.` 开头），最后查内置 catalog。C/C++ 文件经 `resolve_config` 取得 `.clang-format` 的有效规则、诊断和查找依赖；有 TextMate 语法的文件使用 `Language::TextMate`；其他文件为 PlainText。未命名文档使用调用方指定的语言。

`FileState`（`Workspace::file`）保存路径、BOM、已保存基线与修订、配置来源与诊断；编辑层不持有文件状态。

- 打开、新建、另存和 `relocate` 时配置错误不阻止操作：C++ 文件使用 `set_fallback_style` 设置的预设（对应 `cpp-fallback-style` 选项），原因记在 `FileState::config_problem`，打开时显示在消息行。
- 重新加载时配置有错误，保留已有语言规则。
- `reload_configuration` 显式重读并应用规则，保留文本、选区和历史；出错时返回错误，规则不变。
- 常规保存不重新解析配置；另存到新路径时解析目标路径的配置。保存请求记录准备时的配置代次：若之后语言已被切换，确认时保留新的选择，目标路径的配置仍记入 FileState。

## 保存请求与确认

保存分三步：

1. `prepare_save` 捕获当前快照、BOM、目标路径和磁盘基线，预留目标路径，并结束当前撤销分组。`check_save` 只做同样的检查、不预留，供调用方提前放弃无法保存的操作。
2. `FileService::write` 写出快照，返回单次使用的 `SaveCompletion`。
3. `finish_save` 校验请求归属并确认实际写出的快照：更新路径、已保存基线和配置，再次结束撤销分组。

`Workspace::save` 是同步组合。请求执行期间文档可以继续编辑，确认不替换当前文本、不移动光标。`FileUpdate::saved_revision` 是实际写出的修订，`dirty` 表示当前内容是否仍未保存。准备与确认都是历史边界，因此撤销能回到已保存的内容。

每个文档同时只有一个保存请求，请求完成前保留目标路径并阻止关闭。未执行的请求可以用 `cancel_save` 取消，直接丢弃也会排队取消，两者都输出 `FileError::Cancelled` 终态，宿主据此结束相关等待。写入开始后请求与预留保持有效，不能通过取消解除。

`SaveId` 在工作区内唯一，结果通过文档身份与 SaveId 关联到请求。结果可以用 `finish_save` 显式确认；被丢弃时，成功或失败连同原始快照排队回原工作区。`poll_file_results` 在所有者线程应用这些通知并返回带文档身份的 `FileResult`；其他文件生命周期入口也会先处理通知，产生的结果保留到下一次 poll，失败结果不影响无关操作。

同步写入发生 panic 展开时，请求排队要求工作区核对磁盘：内容与请求快照一致则确认保存，否则报告 `Interrupted` 并保留原基线；核对完成前预留有效。

请求持有原工作区的弱引用。工作区释放后，尚未开始的读写返回 `StaleCompletion`；已开始的同步 I/O 可以完成，宿主关闭工作区时应等待它们退出。通知的投递与文件 I/O 都不直接修改模型。

## 写入与冲突

写入使用 tempfile 在同目录创建的临时文件，直接写出 BOM 与 rope chunks，不生成全文字符串。已有文件的权限复制到临时文件；新文件按 0666 创建，受 umask 限制。内容 `sync_all` 后替换目标；通过符号链接打开的文件写入解析后的目标，链接本身保留。

已有目标在写入前和替换前各与加载或上次保存的基线逐字节比较；内容变化、被删除或被其他类型的条目替换都报告 `Conflict`，不确认保存。新目标以不覆盖的方式发布，所以另存不会覆盖已有文件或其他已打开文档。

这些检查不是与其他进程之间的原子比较并替换，最后一次检查与替换之间仍有竞争窗口。保存不同步目录，不保证断电后的完整性，也不保留扩展元数据。

写入失败保留编辑内容、文件绑定和已保存基线。`externally_modified` 单独比较磁盘与基线（原先存在的文件消失也算外部变化），不把外部变化算作本地编辑，也不自动替换文档。

## 重新加载

`reload_for` 以指定会话为发起者，撤销时恢复该会话的选区；应用层传入发起视图的会话。`reload` 以默认会话为发起者。

- 有本地未保存内容时要求 `discard=true`；保存请求执行期间返回 `Busy`；读取失败时编辑状态不变。
- 成功时保留文档身份，用一个 `ReloadText` 事务只替换前后缀之间不同的部分，未变部分的位置照常映射；同时按新配置设置语言，更新 BOM 与磁盘基线，结束撤销分组。
- 返回 `ReloadUpdate`，包含编辑更新和文件更新；文件更新没有保存请求身份。
- 重新加载的文本可以撤销，磁盘基线仍是最后读取的内容。配置与编码元数据不进入文本历史。

## 未保存状态与关闭

`Workspace::is_dirty` 比较当前内容和 BOM 与已保存基线，不比较修订号：撤销回到相同内容时文档重新变为已保存。比较基于 rope，不生成连续全文，同长度修改时可能扫描文本。没有基线的文档在有路径、有内容或有 BOM 时算未保存；scratch 文档永不算未保存。

`close` 拒绝有未保存内容或正在保存的文档。`discard_document` 明确丢弃，同样要求保存请求已经结束。关闭只移除文档和路径注册，不修改磁盘。
