# 文件服务与文档生命周期

文件服务将磁盘操作与编辑状态分开。`files::FileService` 读取文件、解析路径配置并写入不可变快照；`files::Workspace` 管理已打开文档、路径注册和保存请求，协调读取与保存结果。工作区拥有各文档的控制器，`editor_mut` 返回 `Editing` 能力句柄，提供命令、会话和查询接口；句柄无法替换控制器或改写文件绑定。同一文档的多个会话共享文件状态。

## 打开与文档身份

`Workspace::open` 返回 `DocumentId`。路径先规范为绝对路径并解析符号链接，同一路径再次打开时返回已注册的文档，保留当前编辑内容。文件路径可以通过另存改变，文档身份保持不变。关闭后重新打开得到新的身份。

读取只支持普通文件和 UTF-8，开头的 UTF-8 BOM 作为文件元数据保存，不进入编辑文本。LF、CRLF、单独 CR、tab、space 和文件末尾是否有换行均按原字节保留。无效 UTF-8、目录和读取错误返回 `FileError`，不注册部分加载的文档。

`prepare_open` 对已打开路径返回 `Existing(DocumentId)`，其余路径返回带唯一 `OpenId` 的 `OpenRequest`。文件服务通过 `read_request` 返回 `OpenCompletion`，工作区通过 `finish_open` 校验请求注册后应用读取结果；`open` 是同步组合入口。

每条路径同时只允许一个读取请求。`cancel_open` 可以在读取执行时取消注册，随后到达的旧结果返回 `StaleCompletion`，不注册文档。丢弃读取请求或结果会向原工作区排队取消通知。不同工作区或较早请求的结果不能用于当前请求。`FileService::read` 仍可独立读取 `LoadedFile`，原始读取数据不直接作为工作区注册入口。

`new_document` 创建未命名文档，由调用方指定语言。空文档初始为未修改，输入后为未保存。首次保存必须指定目标路径。`open_or_create` 可以创建尚未写出的命名文档，空的新文件也标记为未保存。文件路径与文档身份分别管理，路径尚未写出时由保存请求预留，防止另一个文档同时占用。

## 配置

已知 C/C++ 扩展名根据文件路径调用 `resolve_config`，获得 `.clang-format` 的有效规则、诊断和查找依赖；其他文件默认使用 PlainText。未命名文档使用显式语言配置。

文档的 `FileState::configuration` 保留配置来源与诊断。`reload_configuration` 显式重新读取并应用规则，保留文本、选区和历史。配置错误返回错误并保持已有规则。常规保存不重新加载配置；另存到新路径时重新解析目标路径配置。

保存请求记录准备时的配置代次。如果请求准备后发生语言切换，保存确认保留新的语言选择；目标路径的解析结果仍记录在文件元数据中。

## 保存请求与确认

保存由三个独立步骤组成：

1. `prepare_save` 捕获当前不可变快照、BOM、目标路径及磁盘基线，并结束当前撤销分组。
2. `FileService::write` 将该快照写入磁盘，返回单次使用的 `SaveCompletion`。
3. `finish_save` 校验请求归属并确认实际写出的快照，更新路径、已保存基线和配置。

`Workspace::save` 是这三个步骤的同步入口。独立请求允许在写入执行或结果确认前继续编辑。确认保存不会替换当前文本或移动光标，`FileUpdate::saved_revision` 仅表示实际写出的修订，`dirty` 表示当前文档是否仍有未保存内容。

保存准备和确认都是历史分组边界。准备之后的输入不会与准备之前的同组事务合并，使撤销能够回到已保存内容。

每个文档同时只允许一个保存请求。请求完成前保留目标路径，并阻止文档关闭。尚未执行的请求可以通过 `cancel_save` 取消；直接丢弃请求也会排队取消。文件服务执行期间，请求与预留继续有效，调用方不能通过取消解除运行中写入的预留。

保存结果可以显式通过 `finish_save` 确认；丢弃结果时，成功或失败及其原始快照自动排队回到原工作区。`poll_file_results` 在工作区所有者线程应用通知并返回带文档身份的 `FileResult`。文件生命周期入口也处理通知，处理产生的结果保留到下一次 poll，失败结果不会导致无关操作失败。前端或宿主应定期 poll 后刷新文件状态。

如果同步写入发生 panic 并展开栈，请求排队要求工作区核对磁盘内容：内容与请求快照一致时确认保存，否则报告中断并保留已有基线。预留在该核对完成前保持有效。

请求持有原工作区的弱生命周期引用。工作区释放后，尚未开始的读写拒绝执行；已经开始的同步 I/O 可以完成。宿主关闭工作区时应等待已开始的写入退出。通知的投递与文件 I/O 不直接修改模型。

## 写入与冲突

写入使用 tempfile 提供的同目录临时文件。BOM 与 rope chunks 直接写出，不需要生成全文字符串。已有文件的权限复制到临时文件，内容同步后再替换目标；通过符号链接打开的文件写入已解析的目标，保留链接本身。

已有目标在写入前及发布前分别与加载或上次保存的基线逐字节比较。磁盘内容变化、删除或被不同类型的条目替换均报告冲突，不确认保存。新目标通过不覆盖已有条目的发布方式创建；另存不会覆盖已有磁盘文件或其他已打开文档。

这些检查能检测检查时存在的外部变化，不提供与其他进程之间的原子比较并替换：已有目标在最后检查与替换之间仍有竞争窗口。内容同步与文件替换也不构成完整的断电恢复保证，目录同步及文件系统扩展元数据属于后续保存策略。

写入失败保留编辑内容、原文件绑定和已保存基线。`externally_modified` 单独比较磁盘基线，外部变化不会被误算成本地编辑，也不会自动替换文档。`reload` 提供显式重新加载，并对本地未保存内容和执行中的保存进行保护，详见[编辑命令](commands.md)。

## 未保存状态与关闭

`Document::is_dirty` 比较当前内容与已保存基线，不能仅比较修订号。撤销恢复相同内容时，即使当前修订更新，文档也重新变为已保存状态。比较基于 rope 内容，不生成连续全文；发生同长度修改时可能需要扫描文本。

`close` 拒绝关闭有本地未保存内容或正在保存的文档。`discard_document` 表达明确的丢弃操作，同样要求保存请求已经结束。关闭只移除文档和路径注册，不修改磁盘文件。

## 验证

文件测试覆盖请求丢弃、结果丢弃、读取取消及旧结果拒绝、跨工作区结果归属、工作线程预留、中断核对，以及 UTF-8 BOM、混合换行和末尾字节的往返，重复路径和符号链接，保存期间继续编辑，历史恢复后的未保存状态，外部修改与删除冲突，写入失败和取消，路径预留，配置重载与另存，以及 Unix 文件权限。

```sh
cargo test --test files
```

`SaveId` 在工作区内唯一，保存结果通过文档身份和 SaveId 共同关联到请求。未执行请求的取消也输出 `FileError::Cancelled` 终态；宿主消费该结果以结束相关等待会话。重新加载的文件更新没有保存请求身份。

应用重新加载通过发起视图的编辑 Session 执行，撤销恢复该会话的原选区。`Workspace::reload_for` 明确接收会话身份；直接使用工作区的 `reload` 则以默认会话为发起者。
